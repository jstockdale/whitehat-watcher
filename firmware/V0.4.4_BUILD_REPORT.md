## Changes vs 0.4.3

### 1. Bootloader RTC watchdog fix (the 0.4.3 ~11s reboot loop)

**Root cause:** 0.4.3 rebooted every ~11–12s with `rst:0x3 (RTC_SW_SYS_RST)`.
The 9s bootloader RTC watchdog runs unfed in the app because
`CONFIG_BOOTLOADER_WDT_DISABLE_IN_USER_CODE` was not set — the app never
feeds or disables it, so it fires ~9s after boot, every boot.

**Fix:** `CONFIG_BOOTLOADER_WDT_DISABLE_IN_USER_CODE=y` added to
`sdkconfig.defaults` (line 58); `idf.py reconfigure` run; verified `=y`
in the generated `sdkconfig`.

**Open mystery:** why 0.4.2 survived the unfed WDT is still under
investigation. Hypotheses: 0.4.2's boot sequence may have incidentally
reset the RTC WDT (e.g. via a code path that touched the watchdog
registers, or different early-boot timing), or its main-loop timing
masked it. Not yet proven — do not assume 0.4.4 is immune by reasoning
alone; confirm on-device that uptime exceeds 60s with no reset.

### 2. Boot-time LED transient queue (John's request)

**Problem:** the 3s startup rainbow flourish (`TR_STARTUP_RAINBOW`) was
stepped on by the BLE-connected green flash (`TR_FLASH_GREEN_3X` /
`TR_SUCCESS`) because transients preempt each other.

**Fix** (`components/led/led.c`, `led.h`): per John's "don't block, queue
with timeouts" direction —
- `boot_queueing_` flag, true from `led_init()` until `led_boot_complete()`.
- While queueing, `start_transient()` enqueues into a depth-8 FreeRTOS FIFO
  (static storage, internal DRAM `.bss`, no heap, no extra task) instead of
  preempting. Full queue → drop new request with a warning; never blocks.
- The 50ms `esp_timer` tick pops the next transient when none is active, so
  boot lights play sequentially to completion.
- Stuck-transient watchdog: a transient running longer than its max + 500ms
  is force-completed with a warning (belt-and-suspenders; the normal
  duration check already completes transients on time).
- `led_boot_complete()` clears the flag and drops leftovers (logged count);
  called from `main()` right after the `watcher input PoC 0.4.4 up` line.
- After boot, transient behavior is unchanged (preempt as before).
- The ERROR/RECORDING "never preempt" guard is preserved on both the
  enqueue path and the queue-pop path.
