Changes

WDT: active watchdog with HAL feeding (S3 RWDT)

BEFORE: CONFIG_BOOTLOADER_WDT_DISABLE_IN_USER_CODE was removed (wrong). ESP-IDF startup then DISABLED the RTC WDT via init_disable_rtc_wdt — the opposite of John's goal. rtc_wdt_feed() doesn't exist on S3.
AFTER: CONFIG_BOOTLOADER_WDT_DISABLE_IN_USER_CODE=y (keeps bootloader RWDT armed). main.c feeds the S3 RWDT via wdt_hal_feed() every 1s in the supervisor loop. Task WDT 5s + panic, INT WDT 300ms unchanged.
If the main loop hangs, the RTC WDT WILL fire (reset reason 7) — the safety net works instead of being silently disabled.

RAM: 8 tasks moved to PSRAM stacks

BEFORE: 8 tasks (snap, snaptest, hid_keepalive, input, input_retry, link_rx, mqtt_native, ww_feed) used internal DRAM stacks.
AFTER: All 8 now use task_psram_create() with stacks in PSRAM. nvs_writer stays internal (NVS constraint). task_psram tracks handles; transient tasks (snap/snaptest/input_retry/ww_feed) use deferred cleanup.
Frees internal DRAM for DMA/camera/seal buffers. Stack sizes in bytes (ESP-IDF convention); audit's 'words' claim was corrected.

RAM: transient heap buffers to PSRAM

BEFORE: eyes snap/snaptest jobs, link JSON/command buffers, ptt base64, mqtt_native MQTT/JSON buffers used internal heap.
AFTER: All moved to heap_caps_malloc(MALLOC_CAP_SPIRAM). wms2.c scratch left as-is (must stay pure C99 for host tests).
Reduces internal heap pressure during seal/MQTT/camera operations.

Known Issues

  • 10-second WDT reboot loop (0.4.5): device reports ESP_RST_WDT (reason 7), ROM reports RTCWDT_RTC_RST. 0.4.6 keeps the WDT active AND feeds it — if the loop was a hung task, the feed fixes it; if it was a real hang, we'll now get a proper WDT panic trace instead of silence.
