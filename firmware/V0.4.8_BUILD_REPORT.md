## Why 0.4.8

Firmware 0.4.7 correctly routed **all** NVS reads and writes through the
dedicated `nvs_task` (internal stack). But 0.4.7 still boot-looped with the
same assert:

```
assert failed: spi_flash_disable_interrupts_caches_and_other_cpu cache_utils.c:159
(esp_task_stack_is_sane_cache_disabled())
```

Root cause (debug agent, decoded 0.4.7 backtrace): **the `nvs_task` itself
was running on a PSRAM stack.**

- `xTaskCreate(nvs_task_fn, "nvs_task", 4096, ...)` allocates the stack via
  `pvPortMalloc(MALLOC_CAP_DEFAULT)` — 4096 words = **16384 bytes**.
- `sdkconfig`: `CONFIG_SPIRAM_USE_MALLOC=y`,
  `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=16384`.
- A 16384-byte allocation is **not** `< 16384`, so the allocator was free
  to place the stack in PSRAM — and did.
- First NVS → flash → cache-disable: the broker's own stack pointer was
  in PSRAM → assert.

The 0.4.7 audit allowlisted `nvs_task` as "internal stack via plain
xTaskCreate" without accounting for the allocator threshold — and the
allowlist entry was the task *name* (`nvs_task`) while the function is
`nvs_task_fn`, so it never actually matched anything.

## Changes

### 1. nvs_task: static DRAM stack via xTaskCreateStatic

**Before:** `xTaskCreate(nvs_task_fn, "nvs_task", 4096, NULL, 5, NULL)` —
allocator-placed 16384-byte stack, landed in PSRAM (v0.4.7 boot panic).

**After (`components/seal/seal_dev.c`):**
```c
#define NVS_TASK_STACK_WORDS 4096
static DRAM_ATTR StackType_t nvs_task_stack_[NVS_TASK_STACK_WORDS];
static StaticTask_t nvs_task_tcb_;
...
if (xTaskCreateStatic(nvs_task_fn, "nvs_task", NVS_TASK_STACK_WORDS,
                      NULL, 5, nvs_task_stack_, &nvs_task_tcb_) == NULL) {
    return ESP_FAIL;
}
```
The stack is linker-guaranteed in internal DRAM — no allocator roulette.
Verified in the ELF: `nvs_task_stack_ @ 0x3fcaa958` (0x3FC8xxxx = internal
DRAM region).

**Boot-time guard:** `nvs_task_fn` now asserts
`esp_ptr_internal(&stack_probe)` on entry and logs the static stack
address — fail fast at boot on any future regression.

**Impact:** Fixes the v0.4.7 boot panic. Same 4096-word size (no sizing
change, placement only).

### 2. audit_psram_flash.py: flash-task stack placement check

**Before:** Allowlist entry `nvs_task` (dead — function is `nvs_task_fn`);
no verification that flash-touching tasks run on internal stacks.

**After:**
- Allowlist corrected to `nvs_task_fn`.
- New `check_flash_task_stacks()`: every allowlisted function **must**
  be created via `xTaskCreateStatic()` with a `DRAM_ATTR` static stack.
  Bare `xTaskCreate()` for a flash-touching task is a **build failure**.
- Negative-tested: the check correctly flags the v0.4.7
  `xTaskCreate(nvs_task_fn, ...)` code.

**Impact:** The exact v0.4.7 failure mode can never ship again — the
build fails before merge-bin.
