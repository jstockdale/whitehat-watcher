## What was built

**Device name (`set_name`)** — real firmware support, serial-console only (refused over MQTT, same as all provisioning):

```json
{"t":"set_name","name":"Watcher-HID"}
```

- Validates 1–32 printable ASCII characters; persists to NVS namespace `dev`, key `dev_name`.
- Loaded before BLE initialization in `main.c`; used for the BLE GAP name, the BLE advertising payload, the boot `ready.name` field, and the device display title at boot.
- Successful reply carries the applied name: `{"t":"ok","cmd":"set_name","name":"<applied>","_mid":"…"}`.
- Files: `components/hid_ble/include/hid_ble.h`, `components/hid_ble/hid_ble.c`, `components/link/link.c`, `components/display/display.c`, `main/main.c`.

**Configurable native MQTT broker + topic prefix** — previously hardcoded to `mqtts://mqtt.offx1.com:8883` / prefix `watcher`:

```json
{"t":"mqtt_broker","url":"mqtts://mqtt.offx1.com:8883"}
{"t":"mqtt_topic","prefix":"watcher"}
```

- Broker accepts `mqtts://` or `mqtt://`; plaintext `mqtt://` logs a warning (no CA pinning yet — encrypted, unauthenticated; same caveat as v0.4.0). URI max 95 chars.
- Prefix accepts a single level `[A-Za-z0-9_-]{1,32}`; rejected otherwise.
- Stored in seal NVS as `mqtt_uri` / `mqtt_prefix`; v0.4.0 defaults remain on a fresh device.
- Runtime topics rebuilt as `<prefix>/command`, `<prefix>/telemetry`, `<prefix>/heartbeat`, `<prefix>/status`.
- Updating broker or prefix restarts/reconnects the native client. Existing `mqtt_cred` continues to carry username/password.
- Files: `components/seal/mqtt_native.c`, `components/seal/include/mqtt_native.h`, `components/link/link.c`, `components/seal/PROVISIONING.md`.
