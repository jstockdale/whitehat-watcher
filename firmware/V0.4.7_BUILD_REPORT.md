## Why 0.4.7

Firmware 0.4.6 moved `mqtt_native` and `ww_feed` onto PSRAM stacks, but both still performed direct NVS reads. At 2026-09-27 11:19–11:20, telemetry showed repeated:

```
assert failed: spi_flash_disable_interrupts_caches_and_other_cpu cache_utils.c:159
(esp_task_stack_is_sane_cache_disabled())
```

The flash driver disables the CPU cache during NVS operations. A PSRAM-stack task behind the disabled cache panics. v0.4.1 proved this for writes (`set_name`); v0.4.6 proved it for reads.

John's directive: rename `nvs_writer` to the simpler `nvs_task`, route **all** NVS reads and writes through it, and harden the FIFO reliability contract.

## Changes

### 1. nvs_task: reader/writer-agnostic (renamed from nvs_writer)

**Before:** Task serialized writes only. Reads were done inline via direct `nvs_get_*` calls from any task context.

**After:** Task handles 9 ops: `READ_U64`, `READ_U8`, `READ_BLOB`, `READ_STR`, `U64`, `U8`, `BLOB`, `STR`, `DEL`. All NVS reads and writes route through the single FIFO queue. Task symbol renamed to `nvs_task` per John's directive ("the abstraction should be reader/writer agnostic").

**Impact:** Fixes the v0.4.6 cache-disabled crash.

### 2. No fire-and-forget: all operations synchronous

**Before:** `seal_dev_nvs_write_u64`, `seal_dev_nvs_write_blob`, `seal_dev_nvs_delete` enqueued without waiting for completion.

**After:** All 9 public APIs are `_sync` and block until the broker completes the operation. The D4 high-water persist now checks the result: on failure, `last_persisted_` is NOT advanced, so we retry on the next accept (previously we couldn't know it failed).

**Impact:** Callers know if the persist succeeded. D4 invariant holds even on NVS errors.

### 3. FIFO reliability: never drop, never reject

**Before:** Queue-full silently dropped operations (logged, returned error). Response timeout returned `ESP_ERR_TIMEOUT` and abandoned the completion object.

**After (John's requirements):**
- **Queue depth 32** with documented sizing: 7 tasks × 1 in-flight op = 7 worst-case; 32/7 = 4.5x headroom. NVS ops complete in <10ms typical; a full queue persisting for seconds means broker deadlock or NVS hang.
- **xQueueSend blocks 5s, then PANICS** on full. A full queue is system-fatal, not a graceful degradation.
- **xSemaphoreTake panics** on broker timeout (10s default). The response path is equally lossless.
- **`done` allocated in INTERNAL RAM** via `heap_caps_calloc(MALLOC_CAP_INTERNAL)`. The broker touches `done->result` during flash/cache ops; PSRAM-backed `done` would reintroduce the exact crash this task prevents.
- **No `abandoned` flag.** The broker never frees `done`; the caller always cleans up after taking the semaphore. No UAF possible.
- **Only NVS hardware errors propagate** (`ESP_ERR_NVS_*`, flash errors). Queue management is never a failure source.

**Impact:** Silent data corruption months later is impossible by design. Failures are loud (panic with backtrace) or propagated.

### 4. NVS stress test (firmware self-test)

**New:** `seal_dev_nvs_stress_test()` — invoked via `{"t":"dbg","cmd":"nvs_stress"}` (serial console only).

- **Phase 1** (single task): write1 → write2 → read == write2 (ordering); write → immediate read (no stale reads).
- **Phase 2** (4 PSRAM-stack tasks × 10 iters, isolated keys): true concurrency, zero drops, all callers unblock.
- **Phase 3** (4 tasks × 10 iters, shared key, mutex-paired write→read): each task's read sees its own write, proving FIFO serialization with no drops or reordering.

Test tasks run on PSRAM stacks via `task_psram_create` — proving PSRAM tasks safely use NVS through the broker.

### 5. Migrated all direct NVS call sites

| Component | Before | After |
|-----------|--------|-------|
| hid_ble (`device_name_load`) | `nvs_open`/`nvs_get_str`/`nvs_close` | `seal_dev_nvs_read_str_sync` |
| net (`load_creds`) | `nvs_open`/`nvs_get_str`/`nvs_close` | `seal_dev_nvs_read_str_sync` |
| wakeword (`nvs_load`/`nvs_save_*`) | `nvs_open`/`nvs_get_u8`/`nvs_set_u8`/`nvs_commit` | `seal_dev_nvs_read/write_u8_sync` |
| mqtt_native (`load_mqtt_creds`/`load_mqtt_net`) | `nvs_open`/`nvs_get_blob`/`nvs_close` | `seal_dev_nvs_read_blob_sync` |

## Blocking/serialization contract (seal_dev.h)

Documented in the header for future developers:

1. Single FIFO queue, strictly ordered — no concurrent NVS access, ever.
2. Callers block consistently — no fire-and-forget, no polling.
3. No out-of-order writes — FIFO guarantees commit order.
4. No stale reads — broker never caches; FIFO gives read-after-write consistency.
5. Never drop, never reject — queue-full or broker-hung = panic.
6. Only NVS hardware errors propagate to callers.
