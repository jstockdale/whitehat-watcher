## The fix: microphone was recording digital silence

**Root cause:** `ptt.c` configured I2S RX mono capture with
`I2S_STD_SLOT_RIGHT`, based on a code comment claiming "Vendor BSP puts the
mic on the RIGHT slot." That comment was wrong:

- The vendor BSP (`sensecap-watcher.h`) uses `I2S_STD_SLOT_BOTH` for mono
  mic capture.
- ESP-IDF's own default for mono mode is `I2S_STD_SLOT_LEFT`.
- The ES7243 is a stereo ADC; the Watcher's single microphone is wired to
  the **left** channel.

Sampling right-only produced all zeros — confirmed on hardware: two PTT
recordings (5.7s and 4.0s) analyzed peak=2/32768, RMS=1. The recording,
chunking, and upload pipeline were all working; the I2S slot mask was the
sole defect.

**Fix** (`firmware/components/ptt/ptt.c`):

```c
/* Vendor BSP uses SLOT_BOTH for mono mic capture. The ES7243
 * is a stereo ADC; the single mic is on the LEFT channel.
 * Sampling RIGHT only (as before) yields all zeros. */
.slot_mask = I2S_STD_SLOT_BOTH,
```

**Also in this release:** `FW_VERSION` bumped from `"0.3.4"` to `"0.3.4.1"`
(`main/main.c`), so the device reports the new version over the link.

## Verification

- `idf.py build` completes clean; no warnings in `ptt.c`.
- Pre-existing (from v0.3.4, not introduced here): `main.c:200` warning
  `passing argument 1 of 'wakeword_set_callback' from incompatible pointer
  type [-Wincompatible-pointer-types]` — the wake-word detection callback
  signature does not match what `wakeword_set_callback()` expects.
  Should be audited before relying on the wake→PTT path.
- Merged image built with `idf.py merge-bin` (reads the correct 0x20000
  app offset from flash_args automatically).
