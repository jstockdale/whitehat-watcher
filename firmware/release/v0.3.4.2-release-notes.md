## What's new in v0.3.4.2

### 1. Command acknowledgment correlation (`_mid`)
- Every command arriving with a `_mid` field now gets it echoed back in the
  `{"t":"ok",...}` / `{"t":"error",...}` response.
- The Watcher Console (v0.4.10+) injects the MQTT envelope id as `_mid` before
  sending to the device, so command ↔ ack pairs can be correlated when
  multiple commands are in flight.
- No behavior change for commands without `_mid` (field simply omitted).

### 2. Touch input refinements
- **Drag dwell reverted to spec:** `DRAG_ARM_MS` back to 1000 ms (the 1.5 s
  trial felt wrong on the bench). `DRAG_ARM_PX` stays at 4 px (tremor deadzone).
- **Tap thresholds:** `TAP_MAX_MS` = 200 ms, `TAP_MAX_PX` = 8 px (kept — good
  for double-tap timing).
- **Tap-on-touch-and-move fixed (structural):** the lift classifier was
  state-blind — a quick 5–7 px flick would exit the deadzone into POINT mode
  (cursor visibly moved) yet still satisfy the tap window on lift, firing a
  spurious click. Tightening thresholds could never fix this. Now only a lift
  from `GEST_CONTACT` (finger never left the deadzone) can be a tap; lifts
  from `GEST_POINT` are pure cursor motion, never clicks.
- **Double-tap support:** a second tap within 400 ms and 12 px of the previous
  tap's anchor fires a double-click (two press/release pairs, 120 ms apart —
  the OS reliably joins these). The first tap's single click fires immediately
  on release — never held hostage waiting for a potential second tap. A fired
  double-tap consumes the pair; any non-tap release breaks a pending pair.

### 3. BLE status race fix
- BLE starts before `display_init()`; a bonded host could reconnect before the
  display was ready, so `on_ble_event(true)` → `display_set_ble(true)` no-op'd
  while the display wasn't ready, and no later event refreshed the label —
  leaving a stuck yellow "BLE waiting..." even though HID was connected.
- After successful `display_init()`, the firmware now calls
  `display_set_ble(hid_ble_connected())` to sync the label with reality.
