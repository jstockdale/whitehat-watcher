Changes

nvs_task stack: xTaskCreate -> xTaskCreateStatic + DRAM_ATTR

BEFORE: Bare xTaskCreate(nvs_task_fn, ..., 4096, ...) allocated the 16384-byte stack via pvPortMalloc(MALLOC_CAP_DEFAULT). With SPIRAM_USE_MALLOC=y + ALWAYSINTERNAL=16384, 16384 is NOT < 16384, so the allocator placed the stack in PSRAM. First NVS->flash->cache-disable panicked (esp_task_stack_is_sane_cache_disabled) — the v0.4.7 boot loop.
AFTER: Static DRAM_ATTR StackType_t nvs_task_stack_[4096] + StaticTask_t TCB, created via xTaskCreateStatic(). Linker-guaranteed in internal DRAM (verified: 0x3fcaa958 in 0x3FC8xxxx DRAM region). Boot-time assert(esp_ptr_internal(&probe)) fails fast on any regression.

audit_psram_flash.py: flash-task stack placement check

BEFORE: Allowlist entry 'nvs_task' was dead (function is nvs_task_fn); no check that flash-touching tasks run on internal stacks. The xTaskCreate allocator threshold hazard was invisible to the audit.
AFTER: Allowlist fixed to nvs_task_fn. New check_flash_task_stacks(): every allowlisted function must be created via xTaskCreateStatic() with a DRAM_ATTR static stack — bare xTaskCreate is a build failure. Negative-tested against the v0.4.7 code (correctly flags it).
