# 0.4.43 post-flash verification — bench sheet (2026-11-08)

Purpose: prove the ES8311 fix landed and the mic actually hears speech, using the
same evidence bar as the loopback runs that root-caused the silence. Nothing in
this sheet authorizes a flash or a device command — each step waits on John's go
in the bench session.

## Where things stand (checked 2026-11-08 23:03 UTC)

- Firmware 0.4.43 built and verified in the bench chat (SHA `f9fd514a…`):
  `ptt_init` creates and opens the ES8311 right after the mic codec probe and
  never closes it, so ADCVREF — the mic's supply, fed via R160 from ES8311
  pin 15 — stays live from boot. TX uses auto-clear so the permanently open
  speaker path idles silent. If ES8311 init fails, PTT still runs but logs a
  loud warning that the mic has no power.
- Staged in the console at 22:48 UTC: transfer `51779c13`, hash OK, flash
  prompt up, awaiting John's Yes click.
- As of the 23:03 UTC telemetry check, the flash had NOT landed yet: device
  still heartbeating on fw=0.4.42.1, baud 750000, rx_ovf=0, log_laps=0,
  console page 0.4.187. Do not treat 0.4.43 as live until step 1 passes.
  (Staged binaries live in console page memory — a page reload before the
  click wipes the staging and forces a re-stage, per the established flow.)

## Why this fix should work — the controlled evidence

Loopback runs on 0.4.42.1, 2026-11-08 (bench chat):

| Run / phase | Condition | RIGHT (mic) result |
|---|---|---|
| Run 1, phase 1 | ES8311 on, quiet room | rms 9, peak 39 — digital floor |
| Run 2, phase 0 | ES8311 OFF, John shouting/tapping | rms 67 — nothing |
| Run 2, phase 1 | ES8311 ON, John shouting/tapping | peak 10016, rms 847 — mic hears |

The only variable that mattered was the ES8311 being powered. Run 1 phase 2
also proved the DAC → AINL → ADC → I2S chain good end-to-end (LEFT Goertzel
9165 on the 1 kHz tone vs 0 baseline), and John heard the tone aloud,
confirming the speaker path is live.

## Gated sequence (each step on John's go)

1. **Confirm the landing, from telemetry only.** Require a `fw-flashed` event
   for transfer `51779c13` AND a subsequent heartbeat naming fw=0.4.43.
   A Yes click alone is not proof (see the 0.4.34 false-landing correction).
2. **Boot-log check.** Confirm the ES8311 init/open succeeded at boot and the
   "mic has no power" warning is absent. Confirm wakeword feed resumes
   (reads climbing, err=0) — it stays armed at boot per the standing design.
3. **PTT victory lap.** One ordinary PTT take with John speaking normally.
   Pass bar, from the loopback baselines: speech clearly present in the WAV,
   levels in the hundreds-to-thousands rms range (shouting measured rms 847 /
   peak 10016), decisively above the old floor (quiet rms 9; ES8311-off
   shouting rms 67). Run speech recognition on the take and report what he
   said, as in prior PTT checks.
4. **Audio delivery completeness.** Watch the whole take's transfer, not just
   its start: delivery still has no flow control, and take 35833 previously
   lost its back half in alternating runs during a post-flash reconnect
   window. A loud-but-truncated take is a delivery bug, not a mic result —
   say which one it is.
5. **Wake word, first real chance.** With the mic fed, try "Hey Muse"
   (wn10_himuse, live since 0.4.37). Detections were 0 for the entire
   starved-mic era, so any detection now is new evidence; zero detections
   with a proven-hot PTT take would move the hunt to the wakeword path
   itself, not back to the mic hardware.
6. **Watch item.** Note any recurrence of the single 0.4.40 interrupt-WDT
   panic in the legacy I2C ISR during an FSM reset — one occurrence to date,
   clean recovery, recurrence unknown. The ES8311 now being permanently open
   changes I2C bus usage, so the first hours on 0.4.43 are the window to watch.

## If step 3 still shows floor levels

- ES8311 warning present in the boot log → init failed; the fix didn't take
  effect regardless of the version string. Read back the build artifact
  before theorizing.
- No warning, PTT floor, but a shouted loopback phase 1 is hot → the
  always-on boot init works and something in the PTT path closes or
  reconfigures the codec afterward.
- Both floor → reopen the mic-audit tree at the ADCVREF/register level
  (docs/mic-audit-2026-11-07.md); do not re-run the phases already proven.
