## Per-WI changes

### WI-1 — observability (flood suppression, poll backoff, heartbeat object)

- `components/sscma_client/src/sscma_client_io_spi.c`
  - `spi_send_cmd_`: the per-attempt `ESP_LOGE` on LOW-gate timeout **removed** (half the wedge's ~24k-line flood); failure now goes to the transition logger.
  - `spi_miso_wait_level_`: timeout `ESP_LOGW` is now **transition-only** (file-static `miso_wait_failing_`: logs once per failure streak, silent until a wait succeeds again).
  - `gate_note_failure_()` / `gate_note_success_()` log the healthy→failing and failing→healthy edges only (`himax gate failing: …` / `himax gate recovered after N consecutive failure(s)`).
- `components/sscma_client/src/sscma_client_ops.c` — process task: poll delay is now the backoff ladder **{1, 10, 50, 250} ms** indexed by consecutive `sscma_client_available()` failures (any success returns to 1 ms; bulk/inited paths untouched). WI-1 summary: one `himax gate still failing, streak=<n>` line per +100 of io streak.
- `components/link/link.c` — heartbeat gains the nested **`himax_link`** object (`state`, `streak`, `gen`, `rec_drain`, `rec_reset`, `rec_rst`, `rec_rail`, `last_rung`) fed by `eyes_himax_link_info()`; the supervisor task was also added to the existing `stack_hwm` task list.

### WI-2 — failure accounting + honest `link_up_`

- `components/sscma_client/include/sscma_client_io.h` + `sscma_client_io_spi.c`: the shared counter lives in the io layer — `sscma_client_gate_streak()`, `sscma_client_gate_streak_age_ms()`, `sscma_client_gate_streak_reset()`, `sscma_client_gate_drain_recoveries()`. Counting hooks sit **in the worker exec paths only** (never the caller-context wrappers): increment on `spi_send_cmd_` LOW-gate timeout, `spi_txn_write_exec` gate timeout, `spi_txn_available_exec` Gate-2 (transmitted, never answered); reset on `spi_send_cmd_` full send, write-exec completion, available full success (via the gate-1 send), read stash-serve completion. An AT-layer error reply is a completed transaction and does not count.
- `components/eyes/eyes.c`: `link_up_` is cleared by the supervisor the moment an episode opens (streak ≥ 25, §3.2) instead of only by recovery/reboot paths, and restored when the episode closes (or by `eyes_recover_camera`/relink success as before). `eyes_link_gen()` / `link_gen_` increment on every successful `eyes_recover_camera` and successful reboot re-link handshake. `eyes_set_crop`/`eyes_set_sensor_opt` transport failures feed the same counter automatically through the io hooks (their existing retry behavior is unchanged).

### WI-3 — drain-before-fail + escalation ladder

- **Rung 1 (drain), io layer:** on an AVAILABLE Gate-1 timeout with streak ≥ 3, `spi_txn_available_exec` makes one bounded **capturing** drain (`spi_drain_capture_`, 64-byte chunks, ≤ 200 ms, into a 4096-byte PSRAM stash in the io struct) while it still holds the io lock + bus (the drain's documented caller contract). Captured bytes return through the exec's normal success path (`*len` = captured count, streak reset, `gate_drain_recoveries_` incremented) and `spi_txn_read_exec` serves the stash **before** clocking (CMD_READ length reduced by the stash take — the stash is exactly the head of the staged stream). The bulk path's discarding `spi_drain_tx_` is untouched.
- **Rung 2 (CMD_RESET resync):** unpark's RESET fallback was factored into `spi_transport_resync_()` (no-gate RESET → 50 ms settle → wait LOW ≤ 100 ms); unpark calls it (behavior-equivalent). New worker transaction `SPI_TXN_RESYNC` + `spi_txn_resync_exec` + public `sscma_client_io_spi_resync()` (2 s submit budget).
- **Supervisor** (`eyes_link_health_task_`, new task `eyes_link_hlth`, 4096-word internal stack, priority idle+3, started at the end of `eyes_init`): polls the streak every 100 ms and runs the ladder (constants below). Rungs ≥ 3 are gated on `!eyes_snap_busy() && !sscma_client_bulk_active(client_) && !sscma_client_io_spi_test_active(io_)` — new accessors in `sscma_client_ops.c` / io layer — deferring in 500 ms slices (bounded ~65 s, aborting the rung if the streak clears). Episode-close credits the last rung executed; drain credit comes from the io counter. `eyes_himax_link_info()` reports state as `up` (streak 0) / `recovering` (rung executing) / `down`.
- **§2.5 re-issue:** `dbg crop` set and clear branches (`link.c`) and the per-strip set in `eyes_capture_strips_` snapshot `eyes_link_gen()` before the call and re-issue **exactly once** on `ESP_ERR_TIMEOUT` with a changed generation, with a log line.

### Timer-probe removal (folded in)

- `eyes.c`: the 0.4.49.1 diagnostic `timer_probe_cb_` / `timer_list_probe_` and all three call sites (`capture_png entry`, `post-bulk`, `post-encode`) are removed. This also drops the probes' per-capture `ESP_LOGI` lines.

### Origin force-tag + eyes_reset policy (§3.3)

- `link.c` `sealed_fwd`: the inner command is force-tagged before the `handle_command(inner)` recursion — `_via_mqtt` always; `_sealed` only when the envelope verified with `rc == WMS2_OK` (a `WMS2_OK_GRACE` acceptance gets `_via_mqtt` but **not** `_sealed`). Host-supplied values are deleted first.
- `link.c` `link_sealed_dispatch(json, len, bool verified)` (signature updated in `link.h`): forces `_via_mqtt`, and sets `_sealed` iff `verified`. `components/seal/mqtt_native.c`: extern updated; `dispatch_verified_body` (both envelope paths verify before calling it) passes `true`; the grace-mode plain-JSON path passes `false`.
- `eyes_reset` handler: serial behavior unchanged (rail default 1). Remote (`_via_mqtt`): refused unless `_sealed`; remote rail default is **0**, with an explicit `"rail":1` in the same sealed command honored.
- `nvs_stress` remains serial-only (unchanged) — see deviations.

## Deviations and notes (flagged, not silent)

1. **§10.2(b) "highest seal scope tier" is implemented as the `_sealed` (cryptographically verified) check.** The shipped WMS2 verify path has a **single pinned commander key and no per-key scope tiers** — `seal_dev_verify_envelope` returns kind/flags/dev_id/ctr/ts but no scope, and reduced-scope keys are an explicitly deferred part of the 2026-10-01 design. `_sealed` is therefore the strongest origin fact the firmware can test; the `eyes_reset` check site is exactly where a future tier test plugs in. If John wants a literal tier gate, the seal header/verifier need a scope field first — that's a seal-design change, not a link change.
2. **Rung-1 hand-off mechanism:** the spec's "return captured bytes through the available exec's success path" is realized via the drain stash + read-serve described under WI-3. The one protocol subtlety: drained bytes are *removed* from the Himax's staged stream, so the following read must not clock them again — hence `spi_txn_read_exec` serves the stash first and issues CMD_READ for the remainder only. Stash cap 4096 B matches the client's read chunking; a longer staged response simply leaves its tail staged for normal flow.
3. **The 1 s continuous-failure floor is applied to rungs 3/4 as well as rung 2** (spec §2.3 phrases it as "rung ≥ 2"). Age grows monotonically during an episode, so this only delays a first rung-3 attempt until 1 s of continuous failure — it cannot starve the ladder.
4. **`nvs_stress` asymmetry kept:** §3.3 changes only `eyes_reset`'s remote policy; `nvs_stress` stays refused for all `_via_mqtt` callers (it is a stress harness, not a recovery action).
5. **Supervisor task stack** is internal RAM (4096 words), not PSRAM: it calls `eyes_recover_camera`, whose reset path suspends tasks and touches NVS-adjacent state — the same reasoning as the existing internal-stack re-link worker. The spec defers stack sizing to soak data; the task is in the heartbeat `stack_hwm` list from day one so the soak can measure it.
6. **§2.5 scope:** re-issue was added at the two `eyes_set_crop` call sites the spec names (dbg crop handler — set *and* clear branches — and `eyes_capture_strips_`). `eyes_set_sensor_opt` already has its own 3-attempt retry with recovery escalation and was left as-is.
7. **Build warnings:** 8 warnings, all pre-existing unused-symbol warnings in code this change does not alter (`sscma_client_spi_park`/`unpark` have no callers, `himax_ready_gpio_init_`, `analyze_frame`, `stream_png_b64`, `png_sink_append`, `stream_frame_b64`, one unused variable in `sscma_client_new`). No new warnings from the 0.4.50 code.
