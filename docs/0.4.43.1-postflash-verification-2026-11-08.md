# 0.4.43.1 post-flash verification — bench sheet (2026-11-08)

Purpose: close out the mic-fix arc. Firmware 0.4.43 already proved the fix;
0.4.43.1 removes the one thing that crashed at the end of the victory-lap
take. This sheet carries forward ONLY the checks that are still open.
Nothing here authorizes a flash or a device command — each step waits on
John's go in the bench session.

## Already proven — do not re-run

From the 0.4.43 session, 2026-11-08 (bench side chat):

- **0.4.43 landed and booted right.** Telemetry `fw-flashed 51779c13` at
  23:11:52 UTC; heartbeat named fw=0.4.43. Boot log on the successor build
  confirms the line that matters: `ES8311 powered (mic ADCVREF supply live)`.
- **PTT capture is FIXED.** The first live take on 0.4.43 transcribed
  perfectly: *"Hey, Muse. Can you hear me? Is this finally working? Hey,
  buddy. You're doing a great job. Let's see how we go."* Levels are hot —
  peaks clip at 32767 — so a gain trim is future polish, not a blocker.
  Take shape: ~6.6 s shipped in 35 chunks, peak 32768 in telemetry.
- **The take-end crash is root-caused, and it was NOT a stack overflow.**
  After shipping, `rec_stop_and_send` ran the take-end mic probe (the
  0.4.38 diagnostic): four rapid close/open cycles on the record codec.
  With the DAC now permanently open (the 0.4.43 change), closing the record
  side is "pended" instead of disabled inside esp_codec_dev's
  paired-channel handling, and the next reopen enables an RX channel whose
  DMA state is gone — LoadProhibited (EXCVADDR=0) in
  `i2s_rx_channel_start`, Core 1. The probe's job was done — it hunted the
  silence, and the silence is dead.
- **0.4.43.1 is the minimal fix.** Only change: the take-end probe call is
  removed (the function stays, uncalled, with a comment recording why).
  Built and verified, SHA `9ca74059…`; staged as transfer `a55991fa`;
  flashed and heartbeat-verified live at 750000 baud in the bench chat
  (2026-11-08 23:56 UTC), boot line confirming ES8311 powered.

## Still open — gated sequence (each step on John's go)

1. **Repeat PTT — the boring-ending test.** One ordinary take, John
   speaking. Pass bar, all three:
   - audio ships complete (chunk count consistent with take length; the
     0.4.43 reference take was ~6.6 s / 35 chunks);

     boundary in telemetry, no panic block;
   - wakeword feed resumes after the take (reads climbing, err=0), as it

   mic-fix arc.

   no flow control, and a pre-fix take (35833) lost its back half in
   alternating runs during a post-flash reconnect window — unexplained.
   Confirm this take's WAV duration matches the spoken take; a
   loud-but-truncated result is a delivery bug, not a capture result.

   "Hey Muse" (wn10_himuse, live since 0.4.37). Detections were 0 for the
   entire starved-mic era. A detection now is new evidence; zero detections
   alongside a proven-hot PTT take moves the hunt to the wakeword path
   itself (feed levels into the AFE, model selection), NOT back to the
   mic hardware.
4. **Watch item — I2C interrupt-WDT panic is now a pattern.** Second
   sighting 2026-11-08, during the recovery boot after the take-end crash
